# YOLO 目标检测模型训练实践作业要求

## 一、作业概述

### 1.1 作业主题
每位组员独立完成一次 YOLO 目标检测模型的完整训练实践，并以文档形式完整呈现自己的训练过程。本作业的最终交付物是一份**“过程文档”**，而不是一个模型文件或一组精度数字。

训练实践需要覆盖以下完整链路：**选题与环境搭建 → 数据采集与清洗 → 数据标注 → 数据集组织与配置 → 模型训练 → 问题排查与迭代 → 评估与总结**。文档必须让读者能够按图索骥地复现你走过的每一步。

### 1.2 两个“不限”
- **物种不限：** 检测对象完全自选。可以检测猫狗、花卉、水果蔬菜、交通标志、安全帽、口罩、烟头、垃圾桶满溢、乒乓球……任何你感兴趣、且能够合法获取图像的目标类别都可以。建议从自己身边容易拍到的对象入手，数据采集会顺利得多。
- **模型不限：** YOLO 系列版本自选（YOLOv5、YOLOv8、YOLOv11 等均可），模型规模自选（n/s/m/l/x 均可）。没有 GPU 的同学可以选择最小规模模型配合小数据集在 CPU 上完成训练，不影响作业评分。

### 1.3 一个“强调”
本作业强调过程而非结果。mAP 是 0.9 还是 0.5 不重要，重要的是：
- 你是否真的走完了“从原始图片到可用模型”的全流程；
- 你在每个环节遇到了什么问题，是如何定位、如何解决的；
- 你的标注是否规范、数据集组织是否合理；
- 你是否根据训练反馈进行过至少一轮迭代改进。

一份如实记录了三次失败和两次迭代的文档，得分一定高于一份只有一条训练命令和一张漂亮曲线图的文档。

## 二、交付物要求

### 2.1 必交材料清单

| 序号 | 材料 | 要求说明 |
| :---: | :--- | :--- |
| 1 | **过程文档（核心交付物）** | Word 或 PDF，按第 2.2 节的结构撰写，正文不少于 1500 字（不含代码与图片），截图、表格、代码块齐全 |
| 2 | **数据集说明与样例** | 数据集规模、类别定义、划分比例的说明；附 5—10 张标注截图（标注工具界面原图） |
| 3 | **训练记录证据** | 训练日志截图或训练曲线图（loss、mAP 等），至少覆盖最终一轮完整训练 |
| 4 | **推理验证结果** | 不少于 5 张模型推理结果图，其中至少包含 2 张“效果不理想”的 bad case 及原因分析 |

> **选交材料（加分项）：** `data.yaml` 与训练命令、自己写的数据校验/格式转换脚本、模型导出的 ONNX 文件及推理演示小视频（1 分钟以内）。

### 2.2 过程文档的结构要求
过程文档必须包含以下八个章节，章节标题可自拟，但内容要点一个不能少：

| 章节 | 名称 | 必须包含的内容要点 |
| :---: | :--- | :--- |
| 1 | **选题说明** | 检测什么对象、为什么选它、应用场景是什么、预期难点 |
| 2 | **环境搭建** | 软硬件环境（操作系统、显卡/CPU、Python 版本）、安装的框架与版本、安装中遇到的问题 |
| 3 | **数据集构建** | 图片来源（自拍/公开数据集/网络爬取）、数量、清洗过程（剔除了什么、为什么） |
| 4 | **数据标注** | 使用的标注工具、类别定义、标注规范（框怎么画、遮挡/小目标怎么处理）、标注中遇到的问题 |
| 5 | **训练配置** | 模型与预训练权重选择、数据集目录结构、`data.yaml` 内容、关键超参数及取值理由 |
| 6 | **训练过程与问题** | 每一轮训练的配置与现象；遇到的问题清单：现象—排查—原因—解决—验证，五要素齐全 |
| 7 | **评估与迭代** | 验证集指标、bad case 分析、针对问题做了什么迭代（补数据/调参数/改标注）、迭代前后对比 |
| 8 | **总结与心得** | 最大的收获、最深的坑、如果重做会怎么改进 |

## 三、过程文档各章节写作指引
本章逐章说明“写到什么程度才算合格”。写作时请记住一个总原则：**让没看过你操作的人，仅凭这份文档就能理解你做了什么、为什么这么做、卡在哪里、怎么爬出来的。**

### 3.1 选题说明
- 写清检测对象和类别数量（单类别还是多类别），说明选题理由。
- 预估难点：目标小？遮挡多？类别相似？背景复杂？这些预估会在后面的迭代章节得到呼应。

### 3.2 环境搭建记录
- 用表格列出环境：操作系统、CPU/GPU 型号与显存、Python、PyTorch、Ultralytics（或所用框架）版本。
- 安装中遇到的报错要如实记录：复制关键报错信息、贴上报错截图、写清解决办法（例如 CUDA 版本不匹配时如何降级/升级）。

### 3.3 数据集构建与标注
- **采集：** 说明图片来源与数量。自己拍摄的要说明拍摄场景、角度、光照的多样性；使用公开数据集的要写明来源名称；网络图片要注意版权合规。建议总量 300—1500 张，类别间数量尽量均衡。
- **清洗：** 剔除了哪些图片（重复、模糊、不含目标），剔除比例是多少。
- **标注工具：** LabelImg、Labelme、Roboflow、CVAT 均可，写清安装与基本使用方式，附工具界面截图。
- **标注规范：** 这是本章重点。必须写明：边界框贴边程度、遮挡目标标不标、过小目标标不标、类别标签的命名与含义、漏标误标的自查办法。
- **标注问题：** 如实记录标注中踩的坑，例如：标签格式选错（VOC/COCO/YOLO）、标签文件与图片不同名、类别 id 从 1 开始导致越界、中文路径导致工具崩溃等。
- **格式转换：** 如果标注工具导出的不是 YOLO 格式，说明转换方法（脚本或工具），并给出转换后的标签样例。

### 3.4 训练配置与过程记录
- 给出数据集目录结构（tree 截图或文字树）和 `data.yaml` 完整内容。
- 列出关键超参数（`imgsz`、`epochs`、`batch`、`lr0` 等）并说明取值理由，不许只贴命令不解释。
- **训练记录：** 每一轮训练都要记录：改了什么 → 训练现象（loss 曲线、显存占用、报错）→ 结果如何。推荐用表格管理，下表是建议格式：

| 轮次 | 改动内容 | 现象/问题 | 处理措施 | 结果 |
| :---: | :--- | :--- | :--- | :--- |
| R1 | 默认参数直接跑 | …… | …… | …… |
| R2 | …… | …… | …… | …… |

### 3.5 问题与解决方案（核心章节）
这是全文最重要的章节，评分占比最高。每个问题按五要素书写：
- **现象：** 报错原文或异常表现（贴截图/日志）。
- **排查：** 你做了什么检查、排除了哪些可能。
- **原因：** 最终定位到的根因。
- **解决：** 具体改了什么。
- **验证：** 怎么确认问题确实被解决了。

每人至少记录 3 个真实问题。常见问题方向供参考（写自己真实遇到的，不要照抄）：
- **环境类：** torch 与 CUDA 版本不匹配、pip 源超时、opencv 依赖缺失；
- **数据类：** 标签坐标越界、类别 id 不连续、训练/验证集泄漏（同图重复出现）；
- **训练类：** CUDA out of memory、loss 为 nan、mAP 始终为 0、不收敛或过拟合；
- **效果类：** 小目标漏检、相似类别互相误判、特定光照下误检。

### 3.6 评估、迭代与总结
- 写清你看了哪些指标（Precision、Recall、mAP@0.5、mAP@0.5:0.95），以及你从曲线里读出了什么（过拟合？不收敛？）。
- 至少 2 张 bad case 图，逐一分析失败原因（数据量？标注质量？目标太小？），并说明对应的改进措施。
- 迭代前后要有对比：同一批验证图片、同一评估口径。
- 总结写真实体会：最深的坑、最意外的发现、重做一次会怎么改。

> **⚠️ 红线：** 直接复制网络教程截图冒充自己的训练记录、互相抄袭文档、训练日志与文档描述对不上，均按“真实性与独立性”项 0 分处理。

## 五、时间安排与分工建议
建议用两周完成，参考节奏如下：

| 阶段 | 时间 | 任务 |
| :---: | :---: | :--- |
| **选题与环境搭建** | 第 1—2 天 | 确定检测对象，装好环境并跑通官方 demo |
| **数据采集与标注** | 第 3—5 天 | 完成采集、清洗与全部标注，自查标签质量 |
| **首轮训练与调通** | 第 6—8 天 | 组织数据集、写配置、跑通第一轮完整训练 |
| **迭代优化** | 第 9—11 天 | 针对问题补数据/调参/改标注，至少完成一轮迭代 |
| **撰写文档** | 第 12—14 天 | 整理记录、截图与对比，完成过程文档 |

虽然作业要求每人独立提交一份文档，但组内鼓励互相交流：环境报错可以组内互助，数据集可以组内共享采集（各自的类别和标注必须独立完成），每周例会同步一次进度与踩坑。

## 六、常见问题答疑（FAQ）

### Q1：没有显卡能完成作业吗？
可以。选择 YOLOv8n/YOLOv5n 等最小模型，数据集控制在 300—500 张，`imgsz` 设为 416 或 320，`epochs` 适当减少，CPU 即可跑通。文档中如实说明硬件限制即可，不影响评分。

### Q2：可以直接用别人标注好的公开数据集吗？
可以部分使用，但文档中必须写明来源，并且你仍要完成格式转换、清洗、划分、自查等环节。建议至少在公开数据基础上补拍/补标一部分自己的图片，标注章节才有“自己的过程”可写。

### Q3：训练结果很差，mAP 很低，会扣分吗？
不会。精度不是评分项。结果差但分析到位（为什么差、做了什么尝试、下一步打算怎么改），反而能在“迭代与评估分析”项拿高分。

### Q4：问题不够 3 个怎么办？
一次完全顺利的训练几乎不存在。回看整个过程：环境报错、标注返工、路径错误、显存溢出、指标异常……都是可写的问题。如果真的不足，可以把“预判到并主动规避的风险”作为第四个条目写清楚。
